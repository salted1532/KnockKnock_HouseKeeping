# 넉넉 하우스키핑 - 기능 정의서

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 장르 | 경영 시뮬레이션 + 공포 |
| 시점 | 1인칭 |
| 핵심 컨셉 | 모텔(여관)을 운영하며 반복되는 하루 일과를 수행. 숙박객을 접객하고 신분을 확인하며, 새벽에 탐문을 통해 이상 징후·스토리 단서를 얻어가는 구조 |

## 2. 코어 루프 구조

하루는 4개 시간대로 나뉜다: **아침 → 점심 → 저녁 → 새벽**

시간대는 아래 5단계 진행으로 매핑된다.

```
[아침]  하루일과        : 정해진 업무(청소/정비 등) 오브젝트 상호작용
[점심]  하루일과2/이벤트 : 추가 업무 또는 돌발 이벤트
[저녁]  숙박객 접객      : 체크인 - 대화/질문선택, 신분증 확인, 승인/거절, 객실 배정
[새벽]  자유활동        : 숙박객에게 질문(탐문), 상점 이용, 인벤토리 정리 등
[취침]  침대 상호작용    : 다음 날로 전환. 해당 일차의 뉴스/스토리 진행분 출력
```

취침은 별도 시간대가 아니라 새벽 파트를 마무리하는 전환 트리거로 취급한다.

## 3. 기능 정의 목록

각 기능은 `[SYS-XX]` ID로 관리한다.

### [SYS-01] 1인칭 오브젝트 상호작용 시스템
- 시간대: 전체(주로 아침/점심)
- 설명: 시야 중심 레이캐스트로 상호작용 가능한 오브젝트를 감지 → 프롬프트 UI 표시 → 입력 시 지정된 동작 실행(줍기/청소/스위치 조작 등)
- 필요 요소: 상호작용 가능 오브젝트 태그/인터페이스, 프롬프트 UI, 상호작용 키 입력 처리

### [SYS-02] 일과 태스크 관리 시스템
- 시간대: 아침, 점심
- 설명: 오늘 해야 할 일 목록을 관리. 태스크 완료 시 체크 처리, 전체 완료 시 다음 시간대로 진행 가능
- 필요 요소: 태스크 데이터(할 일 목록), 진행 상태 UI(체크리스트), 태스크-오브젝트 연결

### [SYS-03] 숙박객 접객 대화 시스템
- 시간대: 저녁
- 설명: 손님과의 대화에서 질문 선택지를 고르면 텍스트가 출력되는 분기형 대화 시스템
- 필요 요소: 대화 트리 데이터, 선택지 UI, 텍스트 출력(타이핑 연출 등)

### [SYS-04] 신분증 확인 시스템
- 시간대: 저녁
- 설명: 손님이 제시한 신분증 정보를 확인. 위조/불일치 여부를 플레이어가 직접 판단해야 하는 검증 시스템 (Papers, Please 류)
- 필요 요소: 신분증 오브젝트/클로즈업 UI, 신분증 데이터(진위 플래그 포함), 대조 기준(예: 예약자 명단)

### [SYS-05] 숙박 승인/거절 판단 시스템
- 시간대: 저녁
- 설명: 접객 대화·신분증 확인 결과를 바탕으로 손님을 받을지 거절할지 선택. 선택 결과가 이후 이벤트/엔딩에 영향
- 필요 요소: 승인/거절 선택 UI, 판단 결과 저장(플래그), 거절 시 처리(퇴장 연출 등)

### [SYS-06] 객실 배정 UI 시스템
- 시간대: 저녁
- 설명: 승인된 손님에게 빈 객실을 지정. 객실 현황(공실/배정됨/청소필요 등)을 한눈에 보여주는 UI
- 필요 요소: 객실 데이터(번호/상태/배정된 손님), 객실 배치도 또는 리스트 UI

### [SYS-07] 인벤토리 시스템 (4슬롯)
- 시간대: 전체
- 설명: 최대 4칸까지 아이템 소지. 슬롯 UI에서 아이템 확인/사용/버리기
- 필요 요소: 아이템 데이터, 슬롯 UI, 소지 한도 처리

### [SYS-08] 상점 UI/구매 시스템
- 시간대: 주로 새벽(또는 이동 가능 시간대 전체)
- 설명: 인접한 상점에서 아이템 구매. 재화(돈)와 인벤토리 연동
- 필요 요소: 상점 UI(아이템 목록/가격), 재화 데이터, 구매 시 인벤토리 추가 처리(4슬롯 한도 고려)

### [SYS-09] NPC 이동/경로 시스템
- 시간대: 전체
- 설명: NPC(손님 등)가 정해진 경로(웨이포인트)를 따라 이동하며, 이동 애니메이션(걷기 등)을 재생
- 필요 요소: 경로 데이터(웨이포인트/스플라인), 이동 로직, 애니메이터 연동

### [SYS-10] 새벽 자유활동/탐문 시스템
- 시간대: 새벽
- 설명: 투숙 중인 손님에게 찾아가 질문을 던지고 답변(단서/스토리)을 얻는 시스템. [SYS-03] 대화 시스템을 재사용하되 탐문 전용 질문 세트 사용
- 필요 요소: 탐문 대상 손님 목록, 탐문 전용 대화 트리, 단서 수집 결과 저장

### [SYS-11] 취침 & 일차 전환 시스템
- 시간대: 새벽 → 다음날 아침
- 설명: 침대 상호작용 시 하루를 마감. 해당 일차에 맞는 뉴스/스토리 텍스트(또는 컷신)를 출력한 뒤 다음 날 아침으로 전환
- 필요 요소: 일차별 뉴스/스토리 데이터, 전환 연출 UI, 일차 카운터/저장

### [SYS-12] 시간대 전환/HUD 시스템
- 시간대: 전체
- 설명: 현재 시간대(아침/점심/저녁/새벽)와 다음 할 일을 상시 안내하는 HUD
- 필요 요소: 시간대 상태 관리자, HUD UI

## 4. 데이터 구조 제안 (초안)

| 데이터 | 주요 필드 |
|---|---|
| GuestData | 이름, 신분증 정보(진위 플래그), 배정 객실, 특이사항 플래그, 대화 트리 ID, 탐문 대화 트리 ID |
| RoomData | 번호, 상태(공실/배정됨/청소필요), 배정된 GuestData |
| ItemData | 이름, 아이콘, 사용 효과, 상점 판매가 |
| DayData | 일차, 아침/점심 태스크 목록, 저녁 방문 손님 목록, 새벽 뉴스/스토리 텍스트 |

## 5. 추가 검토 필요 기능 (제안, 확정 아님)

경영+공포 장르 특성상 사용자가 언급하지 않았지만 통상 필요할 가능성이 높은 기능:

- 저장/불러오기(세이브) 시스템
- 하루 마감 정산/평판 시스템 (경영 요소: 수입, 손님 만족도/평판 등)
- 이상 징후·공포 연출 트리거 시스템 (특정 손님 행동/대사 이상 감지 → 공포 이벤트 발동)
- 엔딩 분기 시스템 (승인/거절, 탐문 결과 누적에 따른 분기)
- 퀘스트/단서 진행 트래커 (탐문으로 얻은 단서 모아보기)

기존 프로젝트에 낮/밤 라이팅 볼륨 프로파일 전환 스크립트(doc 0021~0024)가 이미 있어, 시간대 전환 시 조명 연출과 연동 가능.

## 6. 개발 우선순위 제안 (MVP 기준)

1. **1차(코어 루프 성립)**: SYS-01, 02, 03, 04, 05, 06, 11, 12
2. **2차(플레이 편의)**: SYS-07, 08
3. **3차(연출/몰입)**: SYS-09, 10, 그리고 5장의 이상 징후/공포 연출 트리거
