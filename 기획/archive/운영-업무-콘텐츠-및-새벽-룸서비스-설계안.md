# 운영 업무 콘텐츠 & 새벽 룸서비스 설계안

날짜: 2026-09-02
관련: [기능정의서.md](기능정의서.md) SYS-01·02·07·08·10·11, [핵심컨셉-분석및제언.md](핵심컨셉-분석및제언.md) 3·4·12장,
[위협의-정체와-판별-설계안.md](위협의-정체와-판별-설계안.md) 3·4장, `doc/0100`(하루 흐름), `doc/0118`(새벽 노크·문틈 관찰),
`doc/0132`(체크아웃·아침 청소), `doc/0133`(아침 태스크·점심 전환)

## 0. 이 문서가 다루는 것

"미국 소규모 독립 모텔 주인이 직접 다 한다" 는 현실 업무 목록(프런트·하우스키핑·시설·해충·재고·외부업체·야간
사건·돈)을 게임의 4시간대 루프에 어떻게 배치할지 정리한다. 그리고 사용자가 제안한 **새벽 룸서비스 배달 루프**
(주인방 전화로 각 방 요청 확인 → 창고에서 아이템 픽업 → 배달)를 상세 설계한다.

새 시스템을 늘리려는 문서가 아니다. 대부분은 기존 SYS와 하루 루프 위에 **콘텐츠(일차별 데이터)**로 얹고,
실제로 새로 만드는 건 새벽 룸서비스 루프 하나다.

## 1. 원칙 — 업무는 "정상"의 질감, 공포가 그걸 변형한다

붙여준 목록(전구 교체, 침대 정리, 변기 뚫기, 재고 주문…)은 그 자체로 재미있는 콘텐츠가 아니라
**대비를 만드는 배경**이다. 핵심컨셉 3·4장이 이미 말한 것 — "어제 사건이 있던 방을 오늘 청소한다",
"같은 단계의 내용이 날이 갈수록 달라진다".

- **깊이를 위해 업무를 늘리지 않는다.** 지루하지만 현실적인 잡무가 평소의 리듬을 만들고, 거기서
  하나가 어긋날 때 공포가 선다.
- **모든 업무에 일차별 변형이 있다.** 초반: 그냥 전구가 나감. 후반: 전구를 갈아도 방이 계속 어둡다.
- **경제는 생존 보조 수준.** (핵심컨셉 12장) 돈은 문제를 깔끔히 없애는 수단이지만, 돈은 객실 수입에서
  나오고, 고장·해충으로 객실이 줄면 수입이 준다. 후반 봉쇄로 업체·상점이 끊기면 모아둔 부품·현금이
  무의미해진다 → 초반 경영 → 중반 생존 → 후반 농성으로 무게중심이 자연히 이동.

## 2. 붙여준 업무 목록 → 시간대 배치

| 목록 분류 | 주 배치 | 게임에서의 역할 |
|---|---|---|
| 1. 프런트/숙박객 (체크인·키·결제) | 저녁 접객 | `doc/0118` 접객·방배정. 이 문서 범위 밖 |
| 1. 프런트 — 민원·수건/베개 요청·소음·분쟁 | **새벽 (룸서비스 루프, §5)** | 전화 요청 → 창고 → 배달. 소음/분쟁은 새벽 이벤트 |
| 1. 분실물 관리 | 아침 (청소 중 수거) → 프런트 분실물함 | 나중에 되찾으러 오는 손님. 공포 훅: 아무도 두고 갈 수 없는 물건 |
| 2. 하우스키핑 (체크아웃/숙박중 객실) | **아침** | `doc/0132`·`doc/0133`. 14단계로 쪼개지 않음 — 쓰레기/침대 + discovery 훅 2~3개 |
| 2. 비품 보충 (수건·휴지·비누) | 아침 (가벼운 태스크) | 창고 재고 소모 → "재고 떨어짐 → 주문" 압박 루프 (§7) |
| 3. 시설 유지보수 (전구·수도꼭지·문고리·페인트) | **점심 (일과 보드)** | 직접 수리. `Interactable` + 간단 연출 |
| 4. 귀찮은 문제 (물 끊김·에어컨·변기 막힘·천장 누수) | **점심** | "직접 vs 업체" 선택(§4). 방-연결형 문제는 후속 |
| 5. 전기/안전 (차단기·정전·화재경보·가스) | **긴급 이벤트 (§6)** | 시간대 침입형. `DayData`에 일차별 스크립트 |
| 6. 외부 관리 (주차장·정원·제설·간판) | **점심** | 분위기 태스크. 점심 돌발(불법주차 등)의 무대 |
| 7. 해충 (바퀴·쥐·빈대) | 점심 검사 + 저녁 손님 신고 | 빈대 = 객실 판매 중지(경영 압박) + 번짐(느린 압박) + 공포 연출 |
| 8. 재고 관리 | 상시 (창고) | 새벽 배달·아침 보충·점심 수리가 전부 창고에서 나감 (§7) |
| 9. 외부 업체 관리 | 점심/긴급의 선택지 | "직접 vs 호출". 중반부터 전화 무응답 시작 → 후반 완전 불가 (§4) |
| 10. 야간 사건 | **새벽 이벤트 (§6)** | 소음·이상한 소리·침입 시도·화재경보. 새벽 페이오프와 결합 |
| 11. 돈 관리 (급여·공과금·세금·보험) | 취침 정산 + 주간 고지서 | 정산 화면 1개 + 가끔 고지서 이벤트 (§7). 풀 경제 시뮬 안 함 |

## 3. 아침 — 하우스키핑 (요약)

`doc/0132`·`doc/0133`에서 다룸. 이 문서에서 추가하는 것만:

- **비품 보충**을 가벼운 아침 태스크로. 카트에서 수건/휴지/비누를 방에 채움 → 창고 재고 −. 재고가
  일정 이하면 아침 보드/전화 정산에 "주문 필요" 표시.
- **분실물**: 청소 중 발견한 물건 → 프런트 분실물함(인벤토리 아님, 씬 오브젝트). 며칠 뒤 손님이
  되찾으러 옴(저녁 방문객 or 새벽 전화). 공포 훅으로 활용: 그 방에 묵은 손님이 두고 갈 수 없는 물건
  (자기 신분증, 아직 안 온 손님의 짐, 플레이어 소지품).

## 4. 점심 — 시설·외부 관리 + "직접 vs 업체"

기존 설계(울타리 수리·노숙자·불법주차)를 유지하고, 그 위에 시설 유지보수를 얹는다.

### 4.1 일과 보드

`doc/0133`의 사장 메모 = 점심에도 그날의 할 일 2~3개 + 가끔 돌발 1개. 전부 완료해야 접객 테이블로
저녁 전환(기존 `PhaseSwitchEffect` + `TasksCompleteCondition`).

### 4.2 직접 수리 vs 업체 호출 (붙여준 목록 §9)

문제마다 두 갈래:

| | 직접 수리 | 업체 호출 |
|---|---|---|
| 비용 | 낮음 (부품값, 창고 재고 소모) | 높음 (현금) |
| 시간 | 지금, 그 자리 | 다음 시간대/다음날 도착 |
| 결과 | 실패 확률 (부품·숙련도) — 실패 시 악화 | 확실 |
| 후반 | 유일한 선택지 | **중반부터 전화 무응답 → 후반 완전 불가** |

- 업체 무응답은 기존 "불법주차 신고 시 경찰이 안 받음" 연출과 같은 장치. 초반엔 정상 → 어느 날부터
  "지금은 연결이 어렵습니다" → 후반엔 신호음도 없음.
- 이게 경제 압박의 척추: 초반엔 돈으로 편하게 해결 → 도시가 무너지며 돈이 힘을 잃음 → 부족한 부품으로
  직접 버팀.

### 4.3 방-연결형 문제 (후속, 지금 안 함)

붙여준 목록 §4의 "302호 천장 누수 ← 402호 욕실 배관" 같은 공간 퍼즐. 매력적이지만 별도 설계 필요.
지금은 단일 객실 문제만.

### 4.4 해충 — 느린 압박 (붙여준 목록 §7)

- 저녁 접객 중 손님이 "방에 벌레" 신고 or 아침 청소 중 발견.
- 대응: 그 방 판매 중지(배정 불가) → 방역 업체 호출 or 직접 처리 → 며칠 소요.
- 방치하면 인접 방으로 번짐 → 판매 가능 객실이 계속 줄어듦 → 수입 압박.
- 공포 훅: 후반엔 "벌레" 가 벌레가 아님. 방역해도 안 사라짐. 벽 안에서 소리.

## 5. 새벽 — 룸서비스 배달 루프 (신규, 핵심)

### 5.1 왜 이게 좋은가

지금 새벽은 탐문(노크 → 질문)만 있다. 룸서비스 루프는 **모든 방에 노크할 이유**를 주고, 위협 설계안
3.2가 말한 "새벽 = 판별의 페이오프(문틈 야간 관찰)" 를 매 밤 반복 노출한다. 심부름이 관찰의 구실이 된다.

### 5.2 루프

```
새벽 진입
  → 주인방 [전화기] 상호작용 : 각 방의 요청 목록 (자동응답기/메모 로그)
       "203호 — 수건 2장 더"
       "207호 — 베개 하나"
       "205호 — 히터가 안 돌아와요"
       "209호 — ……"        (잡음 / 요청 없음 / 말이 안 되는 요청)
  → 주인방 [창고] : 해당 아이템 픽업 (인벤토리 4슬롯 SYS-07 → 한 번에 다 못 듦, 왕복)
  → 해당 방으로 이동 (빈 복도 = 긴장, 위협 설계안 4.4)
  → [노크]  (기존 KnockEffect / doc/0118 재사용)
  → 문이 살짝 열림 → 문틈으로 아이템 전달
       └ 이 순간이 야간 관찰 (위협 설계안 층3)
  → 요청 처리 = 평판/수입 소폭 + / 무시 = 다음날 컴플레인, 평판 −
  → 행동력(SYS-10) 소모 — 탐문과 같은 풀 공유
  → 전부 처리 or 행동력 소진 → [침대] 취침
```

### 5.3 행동력을 탐문과 공유 — 핵심 선택 압박

새벽 행동력이 **배달 + 탐문 공용**. "오늘 밤 저 방을 조사할까(단서), 요청을 들어줄까(평판·안전)" 가
매 밤의 선택. 의심스러운 방일수록 이 갈등이 커짐 — 요청을 들어주려면 그 문을 열어야 한다.

### 5.4 4슬롯 왕복이 만드는 것

번거로움이 아니라 의도된 페이싱. 창고 ↔ 복도 ↔ 방 왕복이 빈 복도를 여러 번 지나가게 함(위협 설계안
4.4의 폐소 공포 반복), 행동력과 겹쳐 자원 관리, 그리고 "이번엔 뭘 들고 갈까(요청 물건 vs 총)" 선택.

### 5.5 이 루프 전용 공포 훅

- **요청 자체가 이상**: 체크아웃한 방에서 온 요청 / 배정 안 한 방 번호 / 요청 시각이 미래 / 한 방이
  계속 전화 / 내 목소리로 녹음된 요청.
- **창고가 새벽엔 다르다**: 물건이 옮겨져 있음 / 있어야 할 게 없음 / 없어야 할 게 있음(누가 쓴 흔적) /
  창고 안쪽에 문이 하나 더.
- **문이 이미 열려 있음**: 노크가 필요 없는 방 = 나쁜 신호(위협 설계안 4.1 "문이 활짝 열리는 방").
- **잘못 가져간 물건**: 수건 요청인데 히터를 들고 가면 문틈 반응이 다름. 몽유병 방은 뭘 가져가도 받음.
- **미끼**: 몽유병 환자가 있는 방의 요청은 문을 열게 만들려는 것일 수 있음. 전달하려 문틈에 손을 넣는
  순간이 위험.
- **요청 물건을 손님이 안 받음**: 문은 열렸는데 아무도 안 나옴. 아이템을 문 안에 두고 와야 함.

### 5.6 재사용 / 신규

| | 항목 |
|---|---|
| 재사용 | `KnockEffect`·문틈 연출·화면고정(`doc/0118`), `DialogueRunner`(문틈 대사), 인벤토리(SYS-07), 새벽 행동력(SYS-10), `GuestManager` 방↔손님 |
| 신규 (작음) | `DayData`에 방별 요청 리스트(요청 아이템 id, 대사, 이상 플래그) / 주인방 `전화기` Interactable(요청 목록 패널 = `ShowPanelEffect` 재사용) / 창고 픽업 아이템 배치(`PickupEffect` 재사용) / 배달 판정(노크 시 손에 든 아이템 id 대조) |

## 6. 긴급 이벤트 — 시간대 침입형 (붙여준 목록 §5·§10)

화재경보, 정전, 수도관 파열, 침입 시도, 새벽 문 두드리는 소리. 아무 시간대나 끼어든다(주로 새벽·저녁).

- 시스템으로 만들지 않는다 — `DayData`에 일차별 스크립트 1~2개.
- 붙여준 예시("03:21 복도 화재경보기")가 곧 새벽 이벤트 = 새벽 페이오프와 자연스럽게 결합.
- 대응: 확인 → 원인 파악 → 처리(직접 or 호출) → 결과. 초반엔 오작동/사소, 후반엔 진짜.

## 7. 경제 — 취침 정산 + 주간 고지서 (가볍게)

핵심컨셉 12장(경제 비중 축소)을 따른다. 풀 경제 시뮬(급여·세금·보험 개별 관리) 안 함.

- **취침 정산 화면 1개**: 오늘 수입(객실) − 지출(부품·업체·주문) = 잔고. `doc/0100` 침대 취침 연출에 얹음.
- **주간 고지서 이벤트**: 며칠에 한 번 전기료/수도료 청구 → 잔고에서 차감. 못 내면? 초반엔 독촉, 후반엔
  아무도 안 옴(도시가 이미 무너짐).
- **재고 = 창고 하나**: 새벽 배달·아침 보충·점심 수리가 전부 여기서 나감. 상점(SYS-08)에서 보충 →
  후반 봉쇄로 상점 끊김 → 남은 재고로 버팀.

## 8. 일차별 변형 (초반 → 후반)

핵심컨셉 4장의 표를 이 문서 업무로 확장:

| 업무 | 초반 (Day 1~3) | 중반 (Day 4~9) | 후반 (Day 10+) |
|---|---|---|---|
| 아침 청소 | 평범한 방 | 안 가져간 짐, 이상한 얼룩 | 손톱자국, 침대가 따뜻함, 방 수보다 많은 열쇠 |
| 점심 수리 | 전구 나감 | 갈아도 며칠 뒤 또 나감 | 갈아도 방이 안 밝아짐 |
| 업체 호출 | 정상 응답 | "연결이 어렵습니다" | 신호음 없음 |
| 해충 | 개미 몇 마리 | 빈대 → 방 판매 중지 | "벌레" 가 벌레가 아님, 방역 무효 |
| 새벽 전화 | 수건·베개 요청 | 체크아웃한 방에서 요청 | 내 목소리로 녹음된 요청 |
| 창고 | 정상 | 물건이 옮겨져 있음 | 안쪽에 없던 문 |
| 긴급 이벤트 | 화재경보 오작동 | 정전 | 진짜 불, 복도의 발소리 |
| 취침 정산 | 흑자 | 적자 전환 | 숫자가 의미 없음 |

## 9. 안 하는 것 (YAGNI)

- 시설 시뮬레이션(설비별 고장 확률·마모도) — `DayData` 일차별 스크립트로 충분. 노숙자/울타리가
  이미 그 방식.
- 풀 경제(급여·세금·보험 개별 항목) — 정산 화면 1개 + 고지서 이벤트.
- 붙여준 목록 100개를 전부 상호작용으로 — 하루에 회전하는 몇 개만.
- 방-연결형 배관 퍼즐 — 별도 설계.
- 새 매니저 — 새벽 루프는 기존 SYS 재사용 + `DayData` 필드 추가.
- 외부 업체를 NPC로 등장 — 전화 + "다음날 고쳐져 있음" 으로 충분(후반엔 안 옴).

## 10. 미해결 / 확인 필요

1. **새벽 루프 우선순위**: 탐문만 있는 지금 새벽에 룸서비스를 바로 넣을지, 탐문 시스템(SYS-10)
   완성 후 얹을지?
2. **행동력 공유**: 배달과 탐문이 같은 행동력 풀 — 맞나? 아니면 배달은 무료(시간만 소모)?
3. **요청 무시 페널티**: 평판 시스템이 아직 없음. 우선 "다음날 저녁 접객에 컴플레인 대사" 정도로
   시작할지?
4. **점심 "직접 vs 업체"**: 실패 확률 있는 미니게임(수리)까지 만들지, 아니면 "부품 있으면 성공"
   단순 판정?
5. **경제**: 취침 정산 화면을 지금 만들지, 나중으로 미룰지? (수입/평판 시스템 선행 필요)
6. **분실물 되찾기**: 저녁 방문객으로? 새벽 전화로? 별도 손님 타입?
