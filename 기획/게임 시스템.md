## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 가제 | 넉넉 하우스키핑 / 체크아웃 플리즈 |
| 장르 | 모텔 운영 시뮬레이션 + 심리 공포 |
| 시점 | 1인칭 (FPS) |
| 그래픽 | 로우폴리 3D 월드 + 2D 스프라이트 숙박객, RT 픽셀화(PxlCrush) |
| 참고작 | 노 아임 낫 휴먼, 댓츠 낫 마이 네이버, 페이퍼스 플리즈, 디스 워 오브 마인 |

원인 모를 전염병 **"과대 몽유병"** 이 퍼진 미국. 몽유병 환자는 밤마다 좀비/괴물처럼 사람을 습격한다.
플레이어는 모텔 주인으로, TV가 매일 주는 **불완전한 구별법**만으로 숙박객을 받을지 거절할지 판단하며
모텔을 운영한다. 구별법은 나폴리탄 괴담처럼 질병과 무관하거나 이해 불가한 내용이라, 믿을지 말지는
플레이어의 선택이다.

숙박객 중 몽유병 환자가 있으면 밤마다 확률적으로 다른 숙박객이 살해당하고, 환자 수가 정상 숙박객
수보다 많아지면 플레이어가 죽어 게임오버.

### 한 문장 정체성

> 정체를 알 수 없는 위협을, 진위를 확신할 수 없는 규칙으로 판별하면서 모텔을 운영하고,
> 그 판단의 결과를 다음 날 직접 확인하는 게임.

### 핵심 메시지

> 불확실한 정보를 가지고 타인의 생사를 결정하는 것은 정당한가?

구별법(불완전한 정보) · 숙박객(판단 대상) · 승인/거절(판단의 결과) · 대화(인간적 정보) ·
모텔 운영(결과를 책임지는 공간) · 엔딩(판단 기록의 총합) 이 전부 이 한 문장 아래 정렬된다.

## 2. 현재 게임 작동 방식 (구현분)

핵심 축 2개: **`DayPhaseManager`**(시간) + **`Interactable` + `InteractionEffect`**(플레이어 행동).
나머지 시스템은 이 둘이 이벤트/호출로 깨우는 반응 시스템이다.

### 2.1 하루 4단계 순환

**아침 → 점심 → 저녁 → 새벽** (`DayPhaseManager`). 각 단계는 **지정 오브젝트를 상호작용**해서 넘긴다:

| 전환 | 트리거 오브젝트 | 게이트(할일 완료 조건) |
|---|---|---|
| 아침 → 점심 | 게시판 | `MorningTasks` 완료 (`TasksCompleteCondition`) |
| 점심 → 저녁 | 접객 테이블 | `LunchTasks` 완료 (`LunchTasksCompleteCondition`) |
| 저녁 → 새벽 | (자동) | 손님 전원 처리 시 `ReceptionManager` 가 전환 |
| 새벽 → 다음날 아침 | 주인방 침대 | `ActionPoints` 소진 (`ActionPointsDepletedCondition`) → 뉴스 브리핑 경유 |

- 게이트가 열리면 **HUD 유도 마커**(`ObjectiveMarker`) + **벽 너머 외곽선**(`OutlineWhileInteractable`) +
  진입 시 화면 중앙 문구 1회(`ScreenMessage`) 가 "여기로 가라" 를 알림.
- 전환마다 **검정 페이드**(`ScreenFader`) 가 조명/스카이박스/볼륨/포그 스왑(`PhaseVisuals`)과
  앰비언스 교체(`SoundManager`)를 가려준다. 전환 중 마우스 커서 숨김.
- 디버그 키 `N` / `Q` 로 강제 진행.

### 2.2 상호작용 시스템 (컴포넌트 조합)

구 방식(`InteractionType` enum + 거대 switch)을 폐기하고 컴포넌트 조합으로 전환:

```
GameObject
├─ Interactable            ← 플레이어가 찾는 대상 (디스패처, promptType)
├─ InteractionEffect …     ← 실제 동작 (여러 개 스택)
└─ InteractionCondition …  ← 상호작용 가능 여부 게이트 (선택)
```

`Interactable` 의 **Prompt Type** 지정 → 우클릭 "Prompt Type에 맞게 효과 재설정" → 카테고리 표준
효과·콜라이더·레이어·Outline 자동 구성 → 필드 수동 연결.

| 카테고리 | 효과 |
|---|---|
| 여닫기 / 켜고끄기 / 정리하기 | `HingeEffect` / `ChangeObjectEffect` (+`SfxEffect`) |
| 줍기 / 사용 / 밀기 / 걸기 | `PickupEffect` / `SpawnObjectEffect` / `PushEffect` / `HookEffect` |
| 화면고정 / 읽기 | `EnterUIModeEffect` (모니터) / `ShowPanelEffect` (노트·편지·사진) |
| 노크 | `KnockEffect` (새벽 배정 방문 — 화면고정 + 문틈 손님 + 탐문, 행동력 -1) |
| 아침·점심 종료 / 하루 종료 | `PhaseSwitchEffect` / `NewsBriefingEffect` (+`PhaseCondition` + 할일 게이트) |
| 상호작용 / 조사 | `SfxEffect` + `UnityEvent` |

특수 효과: `CheckInGuestEffect`(손님 클릭 체크인), `InteractableProxyClick`(모니터 화면 배경 클릭),
`MonitorViewEffect`(모니터 가벼운 화면고정, 접객 위 중첩).

입력 드라이버 2종: `GazeInteractor`(화면중앙 레이 + E, 벽 너머 차단) / `CursorInteractor`(마우스 좌클릭,
UI 모드 전용, RenderTexture 커서 좌표 보정). `UIInteractionMode` 가 앵커 스택(접객→모니터→노트)으로
플레이어 고정·커서·ESC 한 겹씩 벗김을 관리.

### 2.3 저녁 접객 흐름 (구현분)

```
저녁 진입 → 접객 자리로 자동 착석 → UI 모드(플레이어 고정, 커서)
  손님 큐 (testShuffleAllGuests: 카탈로그 셔플, 투숙 중 제외, 저녁당 최대 maxGuestsPerEvening=5)
  foreach 손님:
     걸어 들어옴 (GuestMover / GuestView 2D 스프라이트, GuestWalkBob 걷기 총총)
     말풍선 대화 (DialogueRunner) — 인사 → 질문 허브(반복 선택) → 선택지 분기 → 종료
        · 숙박 일수 / 선불·후불·2배 / 하우스키핑 여부가 대화에서 결정
        · "신분증 제시" 선택 → 책상 ID 오브젝트 활성 + ID_image 에 이름·생년월일·얼굴 크롭 (ReceptionIdCard)
        · 결정 토픽(선택지 있는 질문)은 한 번 고르면 사라짐 = 번복 불가
     승인 → CRT 모니터로 방 배정(101~110, MonitorRoomBoard) → 열쇠 들고 손님 클릭 = 체크인 (선불이면 이때 입금)
     거절(outcome=Rejected) → 손님 퇴장
  큐 끝 → 지정 앵커로 복귀 → 새벽 전환
```

손님 카탈로그(`NpcCatalog`) = `NpcData` 9명: 나그네 · 회사원 · 거만한 남성 · 젊은 여성 · 노인 ·
트럭기사 · 아버지(와 아들) · 사진작가 · 목사. (상세 [`손님_정보.md`](손님_정보.md))

### 2.4 새벽 탐문 (구현분)

- 자율 이동 복귀. 배정된 방문은 여닫기 대신 **노크**(`KnockEffect`) → 화면고정 → 문 살짝 열림 →
  문틈으로 손님이 나와 질문 대화(`Situation.Dawn`). `refusesDawnKnock` 손님은 거절(`ScreenMessage`).
  새벽이 아닌 시간대의 노크는 항상 무응답.
- **대화가 끝나는 시점**에 행동력 1 소모(`ActionPoints`, 새벽마다 4칸. 중간 ESC 는 소모 안 됨).
  다 써야 주인방 침대에서 잘 수 있음.
- 주인방 `note` 읽기(`SleepwalkerNote`) → 그 일차의 몽유병 구별법 목록(`CampaignData.DayPlan.sleepwalkerHints`).

### 2.5 일차 종료 — 뉴스 브리핑

침대에 누우면 암전 중 `briefingAnchor` 로 **순간이동**(조작 차단) → 왼쪽 대화창에 그날 뉴스
나레이션(선택지 없음) + 오른쪽 인게임 TV 슬라이드(`NightNewsBriefing`, 콘텐츠 = `CampaignData.DayPlan`)
→ 다 보면 아침. 아침 진입 시 화면 중앙에 **"N일차"**(`DayEndTitle`). 매 일차 작동.

### 2.6 객실 생애주기 / 체크아웃 / 하우스키핑

- `RoomController`(방 ×10) — 배정 손님 있으면 체크인 저녁 빼고 체크아웃까지 정문 잠금 + 노크 전환.
  잠금 시 커튼 닫고 소등해 창밖에서 방 안 안 보이게.
- **아침 청소 창** — 체크아웃 아침(대청소) + 하우스키핑 허용 손님의 숙박 중 매일 아침 → 문 열림 +
  침대를 흐트러진 상태로 → 방 안 `Bed` `CleanUp` 상호작용으로 정리. 체크아웃 아침 지나면
  `GuestManager.CheckOut` → 빈방(모니터 재배정 가능).

### 2.7 돈 / 로컬라이제이션 / 환경 연출

- **돈**: `Wallet` 시작금 $100, 1박 $70. 숙박비 = 요금 × 박수. 선불이면 체크인 시, 후불(기본)이면
  체크아웃 아침 입금(현금음). 2배 요금 이벤트(`reject_double_accept`). `MoneyHud`(`$` 초록).
- **로컬라이제이션**: `LocalizationManager` 영/한, 게임 시작 시 언어 확정(런타임 전환 없음).
  Galmuri11 폰트 + LiberationSans 폴백.
- **환경**: `CarSpawner`(거리 자동차, 낮에만) · `ActiveInPhases`(가로등 저녁·새벽 점등) ·

  오클루전 컬링.

### 2.8 통합 아키텍처 원칙

`상호작용-미니게임-연동-설계안` 이 제안한 구조 — "진입 트리거와 판정 로직 분리 / 오버레이 중 월드
입력 잠금 / 판정 결과는 즉시 소비 안 하고 데이터로 저장 후 다른 시간대에 재참조 / 상위 페이즈

## 3. 코어 루프 & 시간대별 콘텐츠

### 원칙 — 반복되지만 의미가 변한다

하루 루프의 **구조는 게임 내내 그대로**, 대신 **같은 단계의 내용이 날이 갈수록 달라진다.**

| 단계 | 초반 (Day 1~3) | 중반 (Day 4~9) | 후반 (Day 10+) |
|---|---|---|---|
| 아침 청소 | 평범한 방 | 안 가져간 짐, 이상한 얼룩 | 손톱자국, 아직 따뜻한 침대, 방 수보다 많은 열쇠 |
| 점심 수리 | 전구 나감 | 갈아도 며칠 뒤 또 나감 | 갈아도 방이 안 밝아짐 |
| 점심 업체 호출 | 정상 응답 | "연결이 어렵습니다" | 신호음 없음 |
| 점심 해충 | 개미 몇 마리 | 빈대 → 방 판매 중지 | "벌레" 가 벌레가 아님, 방역 무효 |
| 저녁 접객 | 정상 손님 | 서로 말이 어긋나는 손님 | 대놓고 이상한 손님 |
| 새벽 탐문 | 잡담 | 어제 한 말과 모순됨 | 문 너머의 것이 손님이 아님 |
| 새벽 전화(룸서비스) | 수건·베개 요청 | 체크아웃한 방에서 요청 | 내 목소리로 녹음된 요청 |
| 창고 | 정상 | 물건이 옮겨져 있음 | 안쪽에 없던 문 |
| 긴급 이벤트 | 화재경보 오작동 | 정전 | 진짜 불, 복도의 발소리 |
| 취침 정산 | 흑자 | 적자 전환 | 숫자가 의미 없음 |
| 취침 | 무사 | 새벽에 문 두드리는 소리 | — |

깊이를 위해 업무를 늘리지 않는다. 지루하지만 현실적인 잡무가 평소의 리듬을 만들고, 거기서 하나가
어긋날 때 공포가 선다. 모든 업무에 일차별 변형이 있어야 이 효과가 난다 (뉴스 텍스트뿐 아니라
청소·수리·대화 각각에 "일차별 버전").

### 3.1 아침 — 지난 밤의 결과를 치우는 시간

**정체성**: 청소가 척추. 청소·정리 행위 자체를 공포 전달 매체로 삼는다. 대부분의 방/날은 평범,
가끔 전날 밤 손님·노크·판정과 연결된 이상 징후. 플레이어는 "오늘은 아무 일 없나?" 를 확인하러 돈다.

**현재 구현**: 체크아웃 방 청소(쓰레기·침대) + 하우스키핑 요청 방 매일 아침 침대 정리 +
후불 손님 숙박비 입금. `MorningTasks` HUD `☐ 침대 개기 N/M` 완료 → 게시판 개방.

**계획된 콘텐츠**:

| 태스크 | 공포 훅 | 상태 |
|---|---|---|
| 방청소 (기존) | 방별 discovery 레이어: 피 묻은 수건, 안 가져간 짐, 안에서 잠긴 문, 아직 따뜻한 침대, 방 수보다 많은 열쇠 | 껍데기 구현, discovery 미구현 |
| 체크아웃 · 열쇠 회수 | 응답 없는 방 / 안 열리는 방 / 모니터엔 빈 방인데 소리 남 / 회수 열쇠 개수 안 맞음 | 방 개폐·`CheckOut` 구현, 태스크 레이어 미구현 |
| 숙박부 / 장부 대조 (프런트) | 전날 승인 기록을 신문 실종자 기사·경찰 전단과 대조. **접객(밤) 판단 → 아침 결과 인과 고리** — 게임 주제 핵심 | 미구현 (패널 1개 + 리스트 비교) |
| 비품 보충 (수건·휴지·비누) | 창고 재고 소모 → "재고 떨어짐 → 주문" 압박 | 미구현 |
| 분실물 관리 | 청소 중 발견 → 프런트 분실물함(씬 오브젝트). 며칠 뒤 손님이 되찾으러 옴. 공포 훅: 두고 갈 수 없는 물건(자기 신분증, 아직 안 온 손님의 짐) | 미구현 |
| 로비/외부 점검, 세탁·쓰레기, 밤 모니터 녹화 확인 | 점심 이벤트 예고편 / 시트에 싼 뭔가 / 프레임에 없어야 할 것 | 후속 |

**추천 시작 세트**: 방청소 + 체크아웃/열쇠 + 장부 대조.

**점심 전환**: 게시판(사장방 배치 추천) = 아침 체크리스트 + 사장 메모. 태스크 미완료로 상호작용 →
남은 할일 표시, 전환 안 함. 완료 → 사장 메모(점심 할 일) + "일과 종료" → 전환. 순수 자동 전환은
비권장(공포 게임에선 "다음으로 넘어갈까" 결정의 순간이 페이싱을 만듦). 메모 자체가 공포 장치:
어느 날 필체가 이상 / 메모가 없음 / 지시가 말이 안 됨.

### 3.2 점심 — 일과 처리 ("직접 vs 업체")

**정체성**: 시설·외부 관리의 일상. 기존 설계(울타리 수리·노숙자 내쫓기·불법주차 신고)를 유지하고
그 위에 시설 유지보수를 얹는다. 점심 돌발 이벤트의 무대.

**현재 구현**: 씬의 `LunchTaskTarget` 을 전부 처리 → `LunchTasks` HUD → 접객 테이블 개방.
실제 이벤트 내용·일차별 변형·점프스케어는 미구현.

**계획된 콘텐츠**:

| 분류 | 내용 | 공포 훅 |
|---|---|---|
| 시설 유지보수 | 전구·수도꼭지·문고리·페인트 직접 수리 (`Interactable` + 간단 연출) | 갈아도 방이 안 밝아짐 |
| 귀찮은 문제 | 물 끊김·에어컨·변기 막힘·천장 누수 → **직접 수리 vs 업체 호출** | — |
| 외부 관리 | 주차장·정원·제설·간판. 불법주차 등 돌발의 무대 | 경찰이 전화를 안 받음, 차 주인도 없음 |
| 해충 | 바퀴·쥐·빈대. 그 방 판매 중지 → 방역(며칠 소요) → 방치 시 인접 방 번짐 | 후반엔 "벌레" 가 벌레가 아님, 벽 안에서 소리 |

**직접 수리 vs 업체 호출** (경제 압박의 척추):

| | 직접 수리 | 업체 호출 |
|---|---|---|
| 비용 | 낮음 (부품값, 창고 재고 소모) | 높음 (현금) |
| 시간 | 지금, 그 자리 | 다음 시간대/다음날 |
| 결과 | 실패 확률 (부품·숙련도) — 실패 시 악화 | 확실 |
| 후반 | 유일한 선택지 | **중반부터 전화 무응답 → 후반 완전 불가** |

초반엔 돈으로 편하게 해결 → 도시가 무너지며 돈이 힘을 잃음 → 부족한 부품으로 직접 버팀.

### 3.3 저녁 — 숙박객 접객 (판별의 시작)

**정체성**: 약한 판단. 근거가 제일 약한 시점(저녁)을 "메인 판단" 처럼 보이게 하되, 실제 페이오프는
새벽. 저녁의 선택이 밤에 시험받는다.

**현재 구현**: §2.3. 손님 큐 · 말풍선 대화 · 신분증 표시 · 모니터 방 배정 · 체크인 · 숙박비.

**계획된 콘텐츠 (3층 판별 중 층 1·2)**:

| 층 | 신호 | 성격 |
|---|---|---|
| **1. 서류** | 신분증 위조(`idCard.forged`), 예약 명단 불일치, 진술 ↔ 서류 모순 | **인간의 거짓말**을 잡음. 감염과 무관. 사기꾼·도망자·잠입자를 걸러냄 |
| **2. 구별법 대조** | TV 기준 + 대화에서 드러나는 인간적 정보 | 약한 사전 확률. 유형별 신뢰도 다름. **오판 유발** |

- **신분증(SYS-04) 역할 재정의**: 몽유병 판별 도구가 아니라 별개의 스크리닝 문제. "사람이냐 /
  거짓말하냐" 두 개의 겹치는 심사가 하나보다 긴장이 크다.
- 승인/거절 후 객실 배정. 거절 시 조르는 손님은 여러 번 요청 → 최종 거절(또는 점프스케어).
- **미구현**: 신분증 위조 판정 로직, 예약 명단 대조 UI, TV 구별법 방송(뉴스 브리핑 슬라이드 +
  일차별 구별법을 `CampaignData` 에 채우기).

### 3.4 새벽 — 탐문 + 룸서비스 (판별의 페이오프)

**정체성**: 가장 강한 판별 신호(야간 관찰)가 나오지만, 손님은 이미 방 안에 들어와 있고 손대는 게
위험하다. 총과 한정된 행동력으로 아직 되돌릴 수 있는 시간. 하루의 기승전결이 여기서 닫힌다.

**현재 구현**: §2.4. 노크 → 문틈 손님 → `Situation.Dawn` 질문 대화, 행동력 4칸, 침대 취침.

**계획된 콘텐츠**:

**(a) 야간 관찰 (3층 판별 중 층 3)** — 문틈으로 본 자세/눈/그림자, 대화 모순, 방의 상태.
가장 강한 신호. 2D 스프라이트 교체로 구현(정상 스프라이트 + 이상 변주). CCTV·방 상태도 신호원.

**(b) 새벽 룸서비스 배달 루프 (신규, 핵심)**:

```
새벽 진입
  → 주인방 [전화기] : 각 방의 요청 목록 (자동응답기/메모 로그)
       "203호 — 수건 2장 더" / "205호 — 히터가 안 돌아와요" / "209호 — ……" (잡음/말 안 되는 요청)
  → 주인방 [창고] : 해당 아이템 픽업 (5슬롯 한도 → 한 번에 다 못 듦, 왕복)
  → 해당 방으로 이동 (빈 복도 = 긴장)
  → [노크] → 문 살짝 열림 → 문틈으로 아이템 전달   └ 이 순간이 야간 관찰
  → 요청 처리 = 평판·수입 소폭 + / 무시 = 다음날 컴플레인, 평판 −
  → 행동력 소모 (탐문과 같은 풀 공유)
  → 전부 처리 or 행동력 소진 → [침대] 취침
```

- **행동력을 탐문과 공유** → "오늘 밤 저 방을 조사할까(단서) / 요청을 들어줄까(평판·안전)" 가 매 밤의
  선택. 의심스러운 방일수록 갈등이 커짐 — 요청을 들어주려면 그 문을 열어야 한다.
- 5슬롯 왕복 = 의도된 페이싱(빈 복도 반복 통과 + 자원 관리 + "요청 물건 vs 총" 선택).
- **전용 공포 훅**: 체크아웃한 방에서 온 요청 / 배정 안 한 방 번호 / 요청 시각이 미래 / 내 목소리로
  녹음된 요청 / 창고 물건이 옮겨져 있음 / 이미 열려 있는 문(노크 불필요 = 나쁜 신호) / 잘못 가져간
  물건에 다른 반응(몽유병 방은 뭘 가져가도 받음) / 미끼 요청(문틈에 손 넣는 순간이 위험).
- **재사용**: `KnockEffect`·문틈 연출·화면고정, `DialogueRunner`, 인벤토리, 행동력, `GuestManager`.
  **신규(작음)**: `DayData` 방별 요청 리스트 / 주인방 전화기 `Interactable` / 창고 픽업 배치 / 배달 판정.

**(c) 긴급 이벤트** — 화재경보, 정전, 수도관 파열, 침입 시도, 새벽 문 두드리는 소리. 시스템으로
만들지 않고 `DayData` 에 일차별 스크립트 1~2개. 주로 새벽·저녁에 끼어듦. 초반엔 오작동/사소,
후반엔 진짜.

### 3.5 취침 — 정산 + 일차 전환

**현재 구현**: 침대 상호작용 → 뉴스 브리핑(§2.5) → 다음날 아침 + "N일차" 타이틀.

**계획된 콘텐츠**:

- **취침 정산 화면 1개**: 오늘 수입(객실) − 지출(부품·업체·주문) = 잔고. 침대 취침 연출에 얹음.
  풀 경제 시뮬(급여·세금·보험 개별 관리) 안 함.
- **주간 고지서 이벤트**: 며칠에 한 번 전기료/수도료 청구 → 잔고 차감. 못 내면 초반엔 독촉,
  후반엔 아무도 안 옴.
- **밤 판정**: 체류 손님 중 `isSleepwalker` 수 대비 정상 숙박객 수로 확률적 살해 처리
  (원안 숫자 규칙, §4.6). 결과가 다음날 아침 청소·뉴스·대화로 드러남.

## 4. 공포 게임 요소 (기획)

### 4.1 가장 큰 위험 — 장르 오해

참고작이 전부 "판별" 계열이라 "사람 검사 게임 + 모텔 스킨" 으로 읽힐 위험. 차별화 지점은 판별 그
자체가 아니라 **판별 이후의 생활**이다.

```
일반 판별 게임 : 손님 확인 → 인간인가? → 입장
이 게임        : 청소 → 모집 → 대화 → 이상 징후 → 구별법 대조 → 입장/배정 결정
              → 다른 손님과의 관계 → 밤 → 사건 → 다음 날 모텔 상태 확인 → 어제 판단을 후회
```

모텔 운영 파트(청소·객실·인벤토리·경제)는 스킨이 아니라 이 차별화의 핵심 축.

### 4.2 모텔이라는 공간

복도·개별 객실·제한된 시야·"객실 안에서 무슨 일이 일어나는지 체크인 시점엔 알 수 없음" 이 이미
공포에 적합. 특히 **"어제 사건이 있었던 방을 오늘 청소한다"** 가 자연스럽게 얹힌다. 숙박객은 방에서
나오지 않고, 모든 조우가 매개된 구도(카운터/문틈/창문)로만 → 복도가 늘 비어 폐소 공포 유지.

### 4.3 구별법 시스템 — 가장 많은 설계 시간을 투자할 콘텐츠

세 유형을 섞어야 "TV가 주는 정보 자체가 진짜인지" 를 플레이어가 끝까지 확신 못 한다. 이게 이
게임의 진짜 공포 대상 — **위협이 아니라 정보 자체에 대한 불신**.

1. **어느 정도 맞는 규칙** — "감염자는 자신의 이름을 불러도 반응하지 않는다." 단, 100%는 아님.
2. **조건부로만 맞는 규칙** — "감염자는 밤에 창문을 열지 않는다." 정상인 중에도 예외가 있어 오판 유도.
3. **인과관계가 설명되지 않는 규칙** — "신발이 문을 향해 있으면 들어가지 마라." 왜인지 설명 안 되지만
   실제로 그 방에서 사고가 남 — 나폴리탄 괴담 특유의 소름.

**목표: 3유형 혼합, 최소 20~30개.** 손님들의 "저녁에 새는 신호" 와 충돌하도록 설계
(예: "가족 얘기를 하는 자를 조심하라" → 중년 부부·가족 여행객과 충돌).

### 4.4 오판(誤判) 시스템 — 필수

실제 감염자가 아닌데 구별법에 우연히 들어맞는 손님이 반드시 존재해야 한다. 플레이어가 의심해서
제거했는데 다음 날 "감염자가 아니었다" 는 결과가 나오는 구조. 이 피드백이 없으면 플레이어는 금방
"수상하면 죽이면 된다" 를 학습해버리고 공포가 사라진다.

- `GuestManager.Verdict {None, Approved, Rejected, Killed}` (플레이어 판단) vs `NpcData.isSleepwalker`
  (내부 정답) 를 **별도로** 저장. 그 괴리를 며칠 뒤 청소/뉴스/대화로 드러내는 사후 이벤트가 필요.

### 4.5 위협의 정체 — 끝까지 밝히지 않는다

- 공식 명칭 "과대 몽유병". **아무도 실체를 모른다.** TV는 매일 설명을 조금씩 바꾼다
  (전염병 → 신경계 질환 → 집단 히스테리 → 종교적 현상…). 이 변동 자체가 "당국도 모른다" 를 전달.
- 손님마다 상충하는 소문. 엔딩 "진실(조건부)" 도 단편만 준다.
- 결과: 플레이어가 죽이는 대상이 **어떤 날은 겁먹은 환자, 어떤 날은 사람 가죽을 쓴 것** — 어느
  쪽인지 끝까지 확신 못 함. 이 애매함은 버그가 아니라 이 게임의 공포다. **해소하지 않는다.**

### 4.6 숫자 규칙의 서사적 포장

원안 로직(감염자 수가 숙박객 수보다 많으면 게임오버, 같으면 확률적 사망 등)은 내부적으로 유지하되,
플레이어에게는 숫자가 아니라 **모텔의 통제 가능성**으로 체감되게 표현:

- 감염자 1명 → 밤에 소규모 사고 가능
- 감염자 2명 → 살해 가능성 증가
- 감염자 3명 → 연쇄 사건
- 감염자가 과반 → 모텔 통제 불가 (게임오버 트리거)

원안: 몽유병 1 : 숙박객 1 → 숙박객 또는 플레이어 사망 / 몽유병 n : 숙박객 n → 숙박객 1명 사망.

### 4.7 3층 판별 (요약)

| 층 | 시점 | 신호 | 성격 |
|---|---|---|---|
| 1. 서류 | 저녁 접객 | 신분증 위조, 명단 불일치, 진술 모순 | 인간의 거짓말. 감염 무관 |
| 2. 구별법 대조 | 저녁 접객 | TV 기준 + 대화의 인간적 정보 | 약한 사전 확률. 오판 유발 |
| 3. 야간 관찰 | 새벽 | 문틈 자세/눈/그림자, 대화 모순, 방 상태, CCTV | 가장 강함. 그러나 이미 안에 있고 손대면 위험 |

뒤로 갈수록 확실하지만 위험. 저녁 = 약한 판단, **새벽 = 페이오프.**

### 4.8 대화와 판별의 연결

접객·탐문 대화는 판별을 보조하는 정보 창구가 아니라, **구별법과 충돌하는 인간적 정보**를 제공하는
장치. 손님이 날마다 자기 이야기를 들려주다가, 어느 날 TV가 그 이야기를 감염 징후로 지목 —
플레이어가 이미 정을 붙인 대상과 규칙이 충돌해야 판단이 무거워진다.

### 4.9 주요 등장인물 (숙박 안 하고 대화만 하는 방문자, `visitorOnly`)

플레이어의 판단 자체를 되돌아보게 하는 화자. 초반 "겉모습으로 판단하면 안 된다" → 중반 "당신은
지금 사람을 판단하고 있다" → 후반 "죽인 사람 중 정말 감염자가 몇이나 있었을까" 로 점점 플레이어를
겨냥.

### 4.10 2D NPC / 통제된 프레이밍

숙박객은 **자유 카메라를 절대 못 얻는다.** 모든 조우가 고정 프레임(접객 = 정위치 착석, 객실 =
문틈 상체, 창문/복도 = 점프스케어용 단발). 이 조건이면 2D가 정답:

- 60명+ × 3D는 팀·연 단위 작업. 2D는 몸 재사용 + 머리/옷 교체로 감당. 얼굴 보고 판단하는 게임이면
  예산을 "읽히는 얼굴 다수" 에 써야 함.
- 대화 시스템이 이미 2D 표정(`NpcData.Portrait`). 풀 2D면 보는 것 = 감정 내는 것.
- 통제된 프레이밍이 2D 최대 약점(돌아서 보면 납작함)을 제거.
- 몽유병 표식 저작이 쉽다 (정상 스프라이트 + 이상 변주). 문틈 구도가 플레이어가 볼 디테일을 정확히
  보게 보장.
- RT 픽셀화 파이프라인과 궁합. 납작한 캐릭터의 언캐니함이 공포에 유리.

**각오할 것**: 접객 걸어오는 연출(`GuestMover`)은 페이드 등장/가려진 채로 / 아트 디렉션 확정 +
레퍼런스 캐릭터 1명 → 양산 / 디자인 라인 유지(문은 항상 틈만, 자유 카메라 앞에 안 옴,
점프스케어·"문 활짝" 은 전용 2D 에셋).

### 4.11 경제 비중 조절

"돈 벌기 → 총 구매 → 의심되는 사람 사살" 이 메인 루프가 되지 않도록 비중을 낮춘다. 상점 재화는
생존 보조 수준(모텔 수리, 식량, 전기·CCTV, 청소용품 / 탄약은 최후 수단). 중후반 도시 봉쇄로 상점
이용이 막히는 구조 유지 — **초반 경영 → 중반 생존 → 후반 봉쇄 농성**으로 무게중심이 자연히 이동.

### 4.12 엔딩 분기

플레이어의 판단 기록(승인/거절/살해 횟수, 오판 횟수, 구별법 신뢰 정도)에 따라 분기:

| 엔딩 | 조건(안) |
|---|---|
| 생존 (정상) | 비감염자 다수 생존, 모텔 봉쇄 성공 |
| 학살자 | 감염자는 거의 없었는데 의심만으로 다수 제거 |
| 감염 모텔 | 너무 관대하게 승인 → 감염자 다수 잔류, 봉쇄 후 내부 사건 |
| 회의주의자 | TV 구별법을 거의 안 믿고 독자 판단 — 생존자는 많지만 감염자도 섞임 |
| 진실 (조건부) | 특정 단서 누적 시 질병 실체의 단편적 정보 공개. 완전한 해답은 안 줌 |
| 배드 | 플레이어가 몽유병 환자에게 살해당함 → 며칠 후 모텔에 아무도 안 남음 |

## 7. 개발 우선순위 / 로드맵

### 서 있는 것

접객 골격(손님 큐·대화·방배정·체크인·체크아웃·숙박비), 4단계 할일 게이트, 일차 종료 뉴스 브리핑,
돈, 로컬라이제이션, 상호작용 시스템, 환경 연출.

### 남은 것 (우선순위)

1. **판별 로직** — 신분증 위조(`idCard.forged`) 판정, TV/노트 구별법을 뉴스 슬라이드·`CampaignData`
   에 채우기, `isSleepwalker` vs `verdict` 를 밤 판정에 연결 (SYS-04·05, §3.3·4.4)
2. **구별법 목록 20~30개** (3유형 혼합) + 손님 "저녁 신호" 와 충돌 설계 (§4.3)
3. **일과 다종화** — 아침 열쇠 회수·장부 대조, 점심 실제 이벤트·일차별 변형·점프스케어 (§3.1·3.2)
4. **밤 판정·살해 시뮬레이션** — 감염자 수 대비 확률 처리, 게임오버 조건, 오판 사후 이벤트 (§4.4·4.6)
5. **새벽 룸서비스 루프** — 전화 → 창고 → 배달, 행동력 공유 (§3.4b)
6. **"밤 판단 → 다음날 결과" 인과 고리** — `StoryFlags` 등 (§2.8)
7. **상점 UI/구매** (SYS-08), 중후반 제한
8. **NPC** 3D→2D 아트 디렉션 확정 + 레퍼런스 1명, 이동/경로, 몽유병 습격 연출
9. **세계관 붕괴 연출** (도시 화재, 분위기 변화), 엔딩 분기 판정 로직

## 8. 안 하는 것 (YAGNI)

- 시설 시뮬레이션(설비별 고장 확률·마모도) — `DayData` 일차별 스크립트로 충분
- 풀 경제(급여·세금·보험 개별 항목) — 정산 화면 1개 + 고지서 이벤트
- 붙여준 운영 업무 목록 100개를 전부 상호작용으로 — 하루에 회전하는 몇 개만
- 방-연결형 배관 퍼즐 (302호 누수 ← 402호 배관) — 매력적이지만 별도 설계
- 대화용 노드 그래프 에디터 / Ink / Yarn — 분기가 얕음(인사 → 평면 질문 목록 → 답변). 진짜 부담은
  분기가 아니라 분량 → CSV 가 답
- `IInteractable` 인터페이스 / 오브젝트별 서브클래스 — `Interactable` + 효과 컴포넌트로 커버
- 이벤트버스/메시징 프레임워크 — `DayPhaseManager` 이벤트 + 싱글턴 참조로 충분한 규모
- 외부 업체를 NPC로 등장 — 전화 + "다음날 고쳐져 있음" 으로 충분 (후반엔 안 옴)
