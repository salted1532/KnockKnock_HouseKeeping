# 위협의 정체와 판별 설계안

날짜: 2026-08-29
관련: [핵심컨셉-분석및제언.md](핵심컨셉-분석및제언.md) 5·6·7·8·9·11장, [기능정의서.md](기능정의서.md) SYS-03~05·10, `doc/0102`(대화·NPC), `doc/0100`(하루 흐름)

## 0. 이 문서가 다루는 것

"과대 몽유병" 컨셉의 내적 모순을 정리하고 해결안을 확정한다. 그리고 그 판별을 **어떻게 화면에 보여줄지**(숙박객 NPC를 2D로 갈지 3D로 갈지)를 함께 정한다. 둘은 같은 문제다 — 판별 신호를 어떻게 전달하느냐가 곧 표현 방식을 정한다.

핵심컨셉 문서가 이미 다룬 것(구별법 3유형, 오판 시스템, 숫자 규칙 서사 포장, 메시지 재정의)은 반복하지 않고 참조만 한다. 이 문서는 그 위에서 **"위협이 대체 뭐고, 플레이어가 그걸 감지할 수단이 실제로 있는가"**에 답한다.

## 1. 문제 정의

원안 설정:
- "과대 몽유병" 전염병. 환자는 밤마다 좀비/괴물처럼 사람을 습격.
- 플레이어는 모텔 주인. TV의 "구별법"만으로 환자를 가려내 승인/거절.
- 구별법은 나폴리탄 괴담처럼 질병과 무관하거나 이해 불가.

내적 모순 3가지:

| 모순 | 내용 |
|---|---|
| **병 ↔ 괴물** | "몽유병"은 의학적 질환을 함의함 → 동정의 대상이지 괴물이 아님. 그런데 행동은 좀비. 이름과 실체가 안 맞음 |
| **신분증 ↔ 감염** | 신분증은 *신원*을 확인함. 감염 여부는 여권에 안 적혀 있음. SYS-04(신분증 확인)로는 환자를 못 잡음 |
| **정보의 신뢰도** | TV 구별법은 대놓고 엉터리라고 설정에 박혀 있음 → 플레이어에게 검증 수단이 0 → 판단이 동전던지기 |

비교작이 작동하는 이유:

| 게임 | 위협 | 판별 근거 |
|---|---|---|
| No, I'm Not Human | 외부인(정체 끝까지 불명) | 방송으로 주어지는 기이한 특징을 눈앞의 대상과 대조 |
| That's Not My Neighbor | 도플갱어 | 규칙집 + 얼굴/디테일의 구체적 오류 |
| Papers, Please | (감염 아님) 서류 위반자 | 관료적 규칙, 명확히 검증 가능 |

셋 다 **"눈앞의 대상 ↔ 체크 기준" 대조가 성립**한다. 현재 몽유병 컨셉은 그게 깨져 있다.

## 2. 해결 방향 3안

**A. TV 구별법을 진짜 메커닉으로.**
부조리하지만 *관찰 가능한* 기준. "오늘: 왼쪽 신발이 오른쪽보다 닳은 자." "오늘: '어머니'라고 말했을 때 안 깜빡이는 자." 플레이어는 실제로 확인할 수 있고, 공포는 "미친 규칙을 목숨 걸고 따르는데 그게 진짜인지 영영 모름". → 핵심컨셉 5장의 3유형 구별법 목록이 이 방식의 콘텐츠.

**B. 표식을 '밤에' 드러나게.**
체크인은 도박. 방에 넣은 뒤 창문/문틈/새벽 대화로 관찰 → 벽 보고 서 있음, 안 잠, 불 안 끔, 같은 말 반복, 그림자가 안 맞음. 진짜 결정은 "어느 방에 넣고 잠글까, 오늘 밤 처리할까". 몽유병 = 야간 행동 장애라는 게 앞뒤가 맞음.

**C. 몽유병 = 거짓 이름.**
정체는 끝까지 안 밝힘(No, I'm Not Human 방식). TV/정부가 붙인 이름일 뿐. 그럼 "병을 감지"가 아니라 "이상함을 감지".

## 3. 채택: B + C (A는 콘텐츠로 흡수)

### 3.1 위협의 정체 = 이름만 있고 실체 불명 (C)

- 공식 명칭 "과대 몽유병". **아무도 실체를 모른다.** TV는 매일 설명을 조금씩 바꾼다 (전염병 → 신경계 질환 → 집단 히스테리 → 종교적 현상…). 이 변동 자체가 "당국도 모른다"를 전달.
- 게임은 정체를 확정하지 않는다. 손님마다 상충하는 소문을 들려준다. 엔딩 "진실(조건부)"(핵심컨셉 11장)도 단편만 준다.
- 결과: 플레이어가 죽이는 대상이 **어떤 날은 겁먹은 환자, 어떤 날은 사람 가죽을 쓴 것** — 어느 쪽인지 끝까지 확신 못 함. 이 애매함은 버그가 아니라 이 게임의 공포다. **해소하지 않는다.** 배드엔딩(아무도 안 남음)이 "사실 플레이어가 문제였을지도"를 암시.

### 3.2 판별 = 3층 신호, 뒤로 갈수록 확실하지만 위험

| 층 | 시점 | 신호 | 성격 |
|---|---|---|---|
| 1. 서류 | 저녁 접객 | 신분증 위조, 예약 명단 불일치, 진술↔서류 모순 | **인간의 거짓말**을 잡음. 감염과 무관. 사기꾼/도망자/잠입자를 걸러냄 |
| 2. 구별법 대조 | 저녁 접객 | TV 기준 + 대화에서 드러나는 인간적 정보 | 약한 사전 확률. 유형별 신뢰도 다름(핵심컨셉 5장). 오판 유발(6장) |
| 3. 야간 관찰 | 새벽 | 문틈으로 본 자세/눈/그림자, 대화 모순, 방의 상태 | 가장 강한 신호. 그러나 이미 안에 들어와 있고, 손대는 게 위험 |

- **SYS-04(신분증)의 역할 재정의**: 몽유병 판별 도구가 아니라 *별개의 스크리닝 문제*. `IdCard.forged`, 예약 명단, `visitorOnly` 인물의 목적. 두 개의 겹치는 심사(사람이냐 / 거짓말하냐)가 하나보다 긴장이 크다.
- **저녁(약한 판단) → 새벽(페이오프)**: 지금 페이싱은 저녁 접객이 "메인 판단"처럼 보이는데 근거가 제일 약하다. 새벽을 페이오프로 만들면 — 저녁의 선택이 밤에 시험받고, 총과 한정된 정신력으로 아직 되돌릴 수 있고 — 하루에 기승전결이 생긴다. `핵심컨셉` 4장(단계별 의미 변화)과 맞물림.

### 3.3 데이터 매핑 (기구현 / 미구현)

| 개념 | 필드·시스템 | 상태 |
|---|---|---|
| 내부 정답(감염 여부) | `NpcData.isSleepwalker` | 있음 (플레이어에게 안 보임) |
| 서류 위조 | `NpcData.idCard.forged` | 있음 (층 1) |
| 대화만 하는 인물 | `NpcData.visitorOnly` | 있음 (핵심컨셉 9장 — 플레이어를 겨냥하는 화자) |
| 플레이어 판단 | `GuestManager.Verdict {None, Approved, Rejected, Killed}` | 있음 (정답과의 괴리 = 오판) |
| 일차별 편성·뉴스 | `DayData.eveningGuests`, `nightNews` | 있음 |
| 구별법 방송 시스템 | — | 미구현 (TV 뉴스 + 일차별 구별법) |
| 야간 관찰 상호작용 | 객실 노크 → 문틈 화면 고정 → 2D 상체 | 미구현 |
| 오판 사후 이벤트 | `Verdict` vs `isSleepwalker` 괴리 노출 | 미구현 |

## 4. NPC를 2D로 — 판별 신호를 통제된 프레이밍으로 전달

### 4.1 관찰 조건 = 항상 통제된 프레이밍

플레이어는 숙박객에게 **자유 카메라를 절대 못 얻는다.** 모든 조우가 고정 프레임:

| 조우 | 프레이밍 |
|---|---|
| 저녁 접객 | 화면 고정(착석), 손님이 카운터 앞 정위치로. 접객 모드는 실제 게임에선 ESC 로 못 빠져나감 |
| 객실 방문 | 문 못 엶. 노크만 → 문이 살짝만 열림 → 화면 고정 → 문틈으로 상체만 보임 |
| 창문/복도 | 점프스케어·연출용 단발 |

숙박객은 방에서 나오지 않는다. 새벽/아침/점심에 돌아다녀도 손님을 직접 마주칠 일이 없다. 모든 손님 처리가 끝나면 자동으로 새벽으로 전환.

### 4.2 이 조건이면 2D가 정답

1. **60명+ × 3D는 팀·연 단위 작업.** 모델링·리깅·스키닝·텍스처·애니메이션(대기/걷기/말하기/화남/몽유 행동)을 60명 고유 인간에. 2D는 몸 재사용 + 머리/옷 교체로 1인 아티스트가 감당. **얼굴을 보고 판단하는 게 핵심인 게임이면 예산을 "읽히는 얼굴 다수"에 써야 하고, 그게 2D.**
2. **대화 시스템이 이미 2D 표정.** `NpcData.Portrait(Expression)` → 스프라이트. 캐릭터가 3D인데 표정은 2D 초상화면 "3D 얼굴은 왜 안 움직여?" 불일치. 풀 2D면 보는 것 = 감정 내는 것.
3. **통제된 프레이밍이 2D의 최대 약점(돌아서 보면 납작함)을 제거.** 접객 = 정위치, 방 = 문틈. 전부 디오라마 구도.
4. **몽유병 표식 저작이 쉽다.** "정상" 스프라이트 + "이상" 변주(눈 이상, 자세 이상, 입 벌림, 그림자 안 맞음). 60개 그리는 건 가능, 60개 3D 리그에 미묘한 이상함 넣는 건 불가능. 그리고 문틈 구도가 **플레이어가 볼 디테일을 정확히 보게** 보장 — 3D는 카메라 각도/조명 때문에 표식이 들쭉날쭉.
5. **RT 픽셀화 파이프라인(PxlCrush)과 궁합.** 페인팅 후 픽셀화가 의도적으로 보인다. 60개 스킨드 메시보다 가볍다.
6. **납작한 캐릭터의 언캐니함이 공포에 유리.** 문틈으로 본 2D 상체가 살짝 안 맞고, 너를 정확히 안 쫓는 눈 — 어중간한 3D보다 무섭다.

### 4.3 2D로 가되 3가지를 각오할 것

1. **접객의 걸어오는 연출 처리.** `GuestMover` 웨이포인트 걷기가 2D가 싸우는 유일한 지점(정면으로 걸어오는 납작 스프라이트 = 발 미끄러짐). 선택:
   - (a) 손님이 카운터에 페이드로 등장(걷기 없음),
   - (b) 걷기가 화면 고정 트랜지션 중 / 일부 가려진 채 일어남,
   - (c) 짧은 접근 + 간단한 bob-슬라이드 + 언캐니함 감수.
   → 정면으로 또렷하게 걸어오는 롱테이크만 피하면 됨.
2. **아트 디렉션 확정.** 빌보드 스프라이트 vs 고정각 쿼드 / 3D 투영 블롭 그림자(3D 방에 접지) vs 없음 / 픽셀 vs 페인팅 / QuickOutline 적용 여부. **레퍼런스 캐릭터 1명 완성 → 나머지 양산.**
3. **디자인 라인 유지 = 2D의 유효 조건.** 문은 항상 틈만. 숙박객은 자유 카메라 앞에 절대 안 옴. "문이 활짝 열려버리는 방"·점프스케어는 **전용 에셋**(화면을 채우는 2D 러시는 OK, "3D 괴물이 복도로 돌진"은 다른 게임). 나중에 봉쇄를 뚫고 쫓아오는 개체가 정말 필요하면 그 하나만 3D 예외 — 기본 60명은 2D 유지.

### 4.4 부수 효과 (긍정)

- 모텔 복도가 늘 비어 긴장 유지. 손님은 방 안에만, 매개된 구도(카운터/문틈/창문)로만 만남 = `핵심컨셉` 3장이 원하는 폐소 공포.
- 3.2의 "층 3 야간 신호"가 2D 스프라이트 교체로 구현 = 저작 저렴 + 플레이어가 정확히 의도된 디테일을 봄.

## 5. 미해결 / 후속

1. **구별법 목록 20~30개** (핵심컨셉 13장 1순위) — A안을 콘텐츠로 흡수하는 실작업.
2. **야간 관찰 상호작용** — 객실 노크 → 문틈 화면 고정 → 2D 상체. `EnterUIModeEffect`(화면고정) 재사용 + 문 살짝 열림 연출. 별도 doc.
3. **오판 사후 이벤트** (핵심컨셉 6장) — `Verdict` vs `isSleepwalker` 괴리를 며칠 뒤 청소/뉴스/대화로 노출.
4. **TV 뉴스 / 구별법 방송 시스템** — `DayData.nightNews` + 저녁 구별법. 설명이 매일 바뀌는 연출.
5. **점프스케어 / "문 활짝" 케이스의 2D 전용 에셋 스펙.**
6. **아트 디렉션 레퍼런스 캐릭터 1명.**

## 6. 결정 요약

- 위협의 정체는 **끝까지 밝히지 않는다.** "몽유병"은 이름일 뿐.
- 판별은 **3층**(서류 / 구별법 / 야간 관찰), 뒤로 갈수록 확실하지만 위험.
- 신분증(SYS-04)은 감염이 아니라 **인간의 거짓말**을 잡는 별개 축.
- 저녁은 약한 판단, **새벽이 페이오프.**
- 숙박객 NPC는 **2D.** 모든 조우가 통제된 프레이밍이라 약점이 없고, 60명+ 규모·표정 시스템·표식 저작·공포 톤 전부 2D가 유리.
