# 0003. AssetsFolder(All, Models pack psx) 머티리얼 깨짐 조사 및 수정 제안

## 날짜
2026-08-06

## 요청 내용
> Assetsfolder폴더 안에 All 이랑 models pack psx에서 사용된 모델링의 머티리얼이 깨진부분을 고쳐줘

## 조사 내용

두 모델 각각 `.fbx`와 `.dae`(Collada) 두 포맷으로 존재한다.
- `Assets/AssetsFolder/All/Models/All.fbx` (+ `All.dae`)
- `Assets/AssetsFolder/Models pack psx/Models/models.fbx` (+ `models.dae`)

두 모델 모두 아직 `SampleScene.unity`에 배치되어 있지 않음(씬 파일에 두 모델의 GUID가 전혀 등장하지 않음). 즉 "깨짐"은 프로젝트 창/인스펙터에서 모델을 열었을 때 보이는 것으로 추정된다.

머티리얼은 별도 `.mat` 파일로 추출되어 있지 않고 모델 파일 안에 내장되어 있다(`materialLocation: 1`, Use External Materials(Legacy) — 이름이 일치하는 외부 텍스처를 자동 검색해서 연결). 프로젝트는 URP(Universal Render Pipeline) + Unity 6000.4.8f1을 사용 중이며, 렌더 파이프라인 자체는 문제 원인이 아니다(모델 임포터가 활성 파이프라인에 맞는 기본 셰이더로 머티리얼을 생성함).

**진짜 원인**: 모델이 내부적으로 참조하는 텍스처 "파일명"과 `Textures`/`Texture` 폴더에 실제로 존재하는 파일명이 일치하지 않아, Unity가 텍스처를 찾지 못하고 해당 슬롯이 빈 채로 남는 것(=깨진 머티리얼로 보임).

`.fbx`(바이너리)와 `.dae`(XML, 텍스트) 양쪽에서 내부에 기록된 텍스처 참조 문자열을 실제 파일 목록과 비교했다.

### 1) `.dae` (Collada) — 광범위하게 깨짐 (권장: 사용 안 함)
Blender가 Collada로 내보낼 때 이미지의 "데이터블록 이름"(중복 시 자동으로 `.001`, `.002`가 붙는 내부 이름)을 그대로 파일명으로 적어버려서, 정상 텍스처인 것들까지도 `Auto.jpg.001.jpg`, `Wire.png.002.png`, `Marble.jpg.001.jpg` 같은 존재하지 않는 파일명을 참조한다. `.fbx`는 이 문제가 없다(아래 참고).

→ **제안**: `.dae`는 애초에 Unity에서 쓸 이유가 없는 백업/중간 산출물로 보임. 수정 대신 `.fbx`만 쓰고 `.dae`는 그대로 두거나(사용 안 함) 필요 없으면 삭제. **`.dae` 텍스처 참조를 일일이 고치는 작업은 제안에서 제외**(실사용 파일이 아니므로 비용 대비 효과 없음).

## 수정 방안 제안

바이너리 `.fbx`를 직접 텍스트 편집하는 건 손상 위험이 커서 하지 않는다. 대신 Unity의 "이름이 일치하는 텍스처를 폴더에서 자동 검색" 동작을 이용해, **모델이 기대하는 파일명 그대로 텍스처 사본을 추가**하는 방식으로 고친다(모델/머티리얼 파일은 건드리지 않음, 텍스처 폴더에 파일만 추가). 재임포트하면 Unity가 자동으로 연결한다.

| 대상 | 조치 | 확신도 |
|---|---|---|
| psx `Wood 6.jpg` | `Wood_06.jpg`를 복사해 `Wood 6.jpg`로 추가 | 높음(이름 패턴상 거의 확실) |
| psx `Wood 7.jpg` | `Wood_07.jpg`를 복사해 `Wood 7.jpg`로 추가 | 높음 |
| All `Marble.jpg` | ? | 후보 3개(`Marble_01/02/03.png`) 중 어느 것인지 판단 불가 |
| All `Metal.jpg` | ? | 후보 7개(`Metal_01~06,08.jpg`) 중 어느 것인지 판단 불가 |
| psx `Bur.png`, `Me.jpg`, `Me4.jpg`, `P10.jpg`, `P12.jpg`, `Te1.jpg`, `Wood (4).jpg`, `Wood 17.jpg` | 대체 후보 없음 | 프로젝트 내 대체 텍스처 없음 — 원본 에셋 팩에서 다시 받거나 새 텍스처를 만들어야 함 |

4. `.dae` 파일들은 그대로 둘지, 삭제할지
