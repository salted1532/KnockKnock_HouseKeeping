# 0014. 에셋 모델 안의 프롭들을 개별 프리팹으로 추출 — 제안서

## 날짜
2026-08-06

## 요청 내용
> 현재 에셋들의 모델에 있는 프롭들을 하나하나 따로따로 프리팹으로 만들수 있어?

확인 질문 후 사용자 답변:
- 범위: **전체 에셋** (All, Models pack psx, House, Pizzeria, Objects_Interior(Village)_Demo, 6twelve, BurgerPiz, Bus_stop, DINER, Laundry, Tacos, Trailer_Park — 지금까지 다룬 모든 팩)
- 프리팹 단위: **최상위 오브젝트 1개 = 프리팹 1개** (하위 부품까지 쪼개지 않음, 예: `Armchair_01` 전체가 하위 부품 포함 프리팹 하나)
- "질문에만 대답하고 진행은 하지마" → **아직 실행 안 함, 승인 대기**

## 왜 파일을 직접 만드는 방식이 아니라 에디터 스크립트인지
지금까지 머티리얼 작업은 `.mat`/`.meta` 텍스트를 제가 직접 작성하는 방식으로 진행했지만, 프리팹은 규모와 방식이 다름:
- **규모**: `All.fbx` 하나에만 최상위 오브젝트가 672개. 요청하신 대로 전체 팩(12개)에 다 적용하면 프리팹이 수천 개가 될 것으로 예상됨(정확한 총 개수는 각 팩의 최상위 오브젝트 수를 다 세어봐야 함).
- **기술적 이유**: `.prefab` 파일은 모델 안의 각 메시(하위 부품 포함)를 참조할 때 Unity가 FBX 임포트 시 내부적으로 생성하는 고유 `fileID`가 필요한데, 이건 Unity가 실제로 모델을 파싱해야 알 수 있는 값이라 제가 파일만 보고 정확히 알아낼 방법이 없음(머티리얼처럼 GUID 하나만 알면 되는 게 아니라, 프롭 하나당 그 하위의 메시/트랜스폼 개수만큼 여러 개의 fileID가 필요하고, 하나라도 틀리면 프리팹이 깨짐). 수천 개 규모에서 손으로 이걸 다 맞추는 건 사실상 불가능하고 위험함.

그래서 제안하는 방식: **Unity 에디터용 C# 스크립트를 하나 작성**해서(`Assets/Editor/PropPrefabExtractor.cs` 같은 위치), Unity 메뉴에 항목을 하나 추가합니다. 사용자가 Unity를 열고 그 메뉴를 한 번 실행하면:
1. 지정한 모델 에셋들(위 12개 팩의 `.fbx`)을 순회
2. 각 모델의 최상위 자식 오브젝트(=프롭) 하나하나를 씬에 임시로 인스턴스화
3. `PrefabUtility.SaveAsPrefabAsset`로 지정 폴더에 `.prefab`으로 저장 (이름은 오브�트 이름 그대로, 예: `Armchair_01.prefab`)
4. 임시 인스턴스 정리

Unity의 정식 API(`PrefabUtility`)가 fileID/GUID 연결을 전부 알아서 안전하게 처리하기 때문에, 규모가 커도 안전합니다. 이게 가장 게으르면서도 안전한 방법입니다(직접 프리팹 YAML을 만드는 건 이 규모에서는 리스크 대비 효율이 나쁨).

## 남은 결정 사항 (진행 승인 전 확인)
1. **프리팹 저장 위치**: 팩별로 `Assets/AssetsFolder/<팩이름>/Prefabs/` 폴더에 각각 만들지, 아니면 `Assets/Prefabs/<팩이름>/`처럼 한 군데에 모을지
2. **이름 충돌**: 여러 팩에 걸쳐 `Tree`, `Wire`, `Plants` 같은 동일 이름 프롭이 있음(같은 이름, 다른 모델). 팩별 폴더로 나누면 충돌 안 나지만, 한 폴더에 모으면 충돌남 → 위 1번 답에 따라 자동 해결되긴 함
3. **콜라이더**: 프리팹에 콜라이더(Box Collider 등)를 자동으로 붙일지, 메시/렌더러만 있는 순수 비주얼 프리팹으로 둘지
4. **스크립트 실행은 사용자가 직접**: 제가 스크립트를 만들어드리면, Unity 에디터에서 메뉴 실행은 사용자가 해야 합니다(제가 Unity를 직접 실행할 수 없음). 실행 후 결과(프리팹 개수, 혹시 실패한 것)를 알려주시면 필요시 스크립트를 수정하겠습니다.
