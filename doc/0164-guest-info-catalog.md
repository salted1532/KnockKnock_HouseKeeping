# 0164 – 손님 정보 문서 정리 (신규 컨셉 20 + 기존 5 통합)

## 요청
사용자가 손님 컨셉 20개 표 제공(외형/평범·이상 행동/공포 포인트/첫 단서). "해당하는 접객 컨셉을 추가하여 현재 존재하는 접객 기획과 합쳐 기획에다가 손님info 문서를 정리해줘." + "목표 60명 중 현재 몇 명 기획됐는지도."

## 조사
- 기존 접객 기획: `기획/기능정의서.md` SYS-03~06·10, `기획/핵심컨셉-분석및제언.md`, `기획/위협의-정체와-판별-설계안.md`(3층 판별), `doc/0102`·`doc/0104`(대화·NPC 시스템 설계·구현).
- 대사 원본: `Assets/My/Data/Dialogue/sample.csv` — id **1~5** 접객+새벽 대사·선택지·분기 완성. 캐릭터화가 전부 CSV 에 있음.
  - 1=떠돌이 나그네, 2=불안한 방문판매원, 3=오만한 손님, 4=혼자 온 여성(새벽 문 안 엶), 5=노인(폭풍 예언·벽 긁는 소리).
- `NpcData` 에셋: `Assets/My/Scripts/Dialogue/NPC_Data/Npc_*.asset` **5개**, 이름 `test1`~`test5`, 플래그 대부분 기본값(placeholder).
- `NpcData` 필드: isSleepwalker, visitorOnly, refusesDawnKnock, stayNights, allowsMorningCleaning, idCard{name,birthDate,photo,forged}.

## 산출물
`기획/손님-정보.md` 신규 작성:
- **0. 진행 현황**: 대사 완성 5 / 컨셉 확정 25(신규20+기존5) / 목표 60. 남은 컨셉 35, 그중 25는 대사 없음.
- **1. 손님 1명의 구성** — NpcData/CSV/Campaign/Verdict 매핑 + 3층 판별(서류/구별법/야간).
- **2. 접객 공통 골격** — sample.csv 구조(Greeting→name·id/purpose/stay+선불/clean/need/reject→checkin|Rejected, Dawn). 카드 템플릿 9칸 정의.
- **3. 기존 5명** — CSV 기준 현 컨셉 + 신규와의 관계. **id 4→#3(혼자 여행 여성), id 5→#14(노인)로 승격**, id 1·2·3 은 신규에 없는 축(무해·불안·오만)이라 유지.
- **4. 신규 컨셉 20** — #1~#20 카드. 각: 외형/접객 톤/요청(stayNights·선불후불·하우스키핑·객실)/서류 특이사항(층1)/저녁 신호(층2)/야간 신호(층3)/첫 단서+배치/데이터 플래그 제안/초·중·후반 배치·감염 톤.
- **5. 3층 분포** — 층1 잡힘 8명, 층2만 6명, 층3 결정적 5명. 오판 후보 #1·#3·#11·#13·#16. 화자 후보 #10·#12.
- **6. 다음 작업** — NpcData 25개 이름·플래그 / sample.csv 25명 확장 / CampaignData 일차 편성 / 단서 배치 / 나머지 35 / TV 구별법 20~30.
