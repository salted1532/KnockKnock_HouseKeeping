# README 갱신 규칙

사용자가 **"README(Readme) 파일 갱신"** 을 요청할 때만 작동한다 (상시 자동 아님).
요청이 오면 아래를 한 번에 처리한다.

1. **범위 파악** — 직전 README 갱신 로그(최신 `doc/*readme*`)를 찾아 그 이후의 `doc/` 번호·git
   커밋 분량을 훑는다.

2. **신규 스크립트 문서화 + 연결** — 마지막 갱신 이후 `Assets/My/Scripts/` 에 추가됐고 문서가
   없는 게임플레이 스크립트마다:
   - `Docs/<ScriptName>.md` 생성 (역할 / 필드 / 동작). 밀접한 보조 스크립트는 한 문서에 묶어도 됨
   - `Docs/Overview.md` 표에 행 추가
   - `README.md` "핵심 스크립트" 표에 행 추가 + `Docs/<ScriptName>.md` 링크
   - 기존 스크립트의 큰 동작 변경으로 기존 `Docs/*.md` 가 틀려졌으면 필요시 갱신

3. **README 본문 갱신**:
   - 기능적 부분 — 핵심 루프, 행동 카테고리·효과 표, 상호작용 설명, 코드 아키텍처 mermaid,
     구현 완료 기능, 수정 필요 표
   - 기획적 부분 — 게임 소개, 시간대별 콘텐츠, 기획 문서 링크
     (`기획/게임 시스템.md`·`기획/손님_정보.md`·`기획/코드-아키텍처.md`)
   - 로드맵 — 완료 항목 반영, 남은 항목 현재 상태로 다시 서술

4. **검증** — README mermaid 가 있으면 `npx -y @mermaid-js/mermaid-cli@11` 로 렌더 확인.
   `git diff --stat`. 코드/에셋은 안 건드림.

5. **세션 로그** — `doc/NNNN-readme-*.md` 에 마지막 갱신 이후 반영분을 정리.

- `Docs/`(스크립트 레퍼런스) 와 `doc/`(세션 로그) 는 별개 폴더
- 문서만 바뀌므로 구현 전 확인 절차는 불필요 (요청 자체가 승인)
